## 0. 🐍🦶 (사족)

내 특기 : 미루기
내 장점 : 해야할 것 미루기^^

농담 아닌 농담으로 항상 배우고 공부하다보면 뒤돌면 잊는 게 내 머리인지라, 블로그를 작성하면서 꼭 기록하자는 마음을 갖고 있었는데.. 그래서 벨로그도 시작했고!
이번에 직접 블로그를 만들어보기로 했다. 근데 만드는 건 좋은데 왜 항상 기록하는 건 미루게 될까나 ^.~ 그래서 지금까지 작업한 것을 기록해보기로 했다.

#### 사실은

왜 블로그를 시작했는지 생각해보면 포폴이 제일 우선이었다. 그리고 SPA만 해본 나는 Next.js을 경험한 적이 실습용 프로젝트밖에 없었기 때문에. 또한 온전히 내 손으로 (분명 AI와 함께임은 분명하지만 🤝) 만든 서비스가 없다는 것이 한몫했다. 프론트엔드로 직무를 옮기겠다고 결심했으니 어쩌면 정석 테크인 블로그 만들기를 해야겠다는 마음도 들었다. (친하지 않은 Next.js와 함께해보자는 것도 덤)

## 1. 목표

여하튼 그래서 이 블로그를 위해 세운 목표가 있다면,

**1. 최대한 안 해본 것을 경험해보자.**

**2. 지속 가능성을 높이자.**

이 2가지였다.

#### 1) 경험하지 못한 것이라 함은

학습을 목표로 최대한 AI활용을 피해왔었는데 이번엔 블로그를 만들면서 프론트엔드 부분이 아닌 인프라나, 깃헙에서의 디펜던시 체크와 같은 자동화 부분을 AI를 통해 최대한 추가하려고 한다. 또한 코드리뷰 등을 AI를 통해 받는 것도 나쁘지 않겠다라는 생각을 했다.
또한 AI가 아니어도 쓰지 않았던 라이브러리 등을 찾아보고 왜 이것을 사용하고자 하는지 비교 후에 사용해 보는 것!

#### 2) 지속 가능성을 높이는 것이라 함은

블로그는 구성도 기능도 중요하겠지만 제일 중요한 건 글을 얼마나 편하게 쓸 수 있는지가 아닐까 싶다. 왜냐면 쓰는 사람이 바로 나예요.. 쓰는 사람이 쓰기 편해야 글은 계속 등록이 되고, 내용이 채워질 것이니까.

(물론 이 모든 것이 나의 포폴로 이어지길 바랄뿐 🙏🙏🙏)

## 2. 기술 스택

일부 개발이 완료된 부분이 있어서 현재까지 적용한 기술 스택과 추가하고자 계획하는 스택을 작성해본다.

### 1. 현재까지 사용한 기술스택

#### 프레임워크 / 렌더링 (Done ✅)

- Next.js 16 (App Router) ➡️ SSR 활용 목적
- React 19 ➡️ Next.js 버전에 맞춰서 19로 진행

#### 콘텐츠(글) 관리 (Done ✅)

- MDX + velite
- rehype-pretty-code + shiki

원조로 사용하고 있던 `Contentlayer`는 활동이 뜸한 상태라 상대적으로 최근에 나와서 활발히 관리되는 velite를 선택했다.
`velite`는 JSON, mdx 파일과 같은 로컬 파일들을 `Zod` 스키마를 이용해 타입 안전(Type Safety)한 어플리케이션 데이터 레이어로 변환해주는 정적 컨텐츠 처리 도구다. `Zod` 스키마로 선언하면 빌드 시점에 실제 파일 내용을 검증까지 하면서, 동시에 그 스키마에서 TypeScript 타입도 자동으로 뽑아내 잘못된 데이터가 프로덕션으로 새어나가지 않도록 해준다.

`rehype-pretty-code`의 경우 코드를 잘 보일 수 있게 하는 코드 하이라이팅 표기가 필요했는데 (아무래도 코드를 첨부하는 일이 많아지게 될테니??) `rehype-pretty-code`는 MDX를 빌드하는 시점(서버/빌드 타임)에 이미 색이 입혀진 HTML을 만들어내서 보내주기 때문에, 클라이언트에서 추가 JS 없이 바로 완성된 상태로 렌더링된다는 점에서 선택했다.

#### 스타일링 (Done ✅)

- Tailwind CSS v4
- @tailwindcss/typography - MDX 본문 스타일링
- Pretendard 폰트, JetBrains Mono (코드)

#### 코드 품질 / 포매팅 (Done ✅)

- TypeScript
- ESLint
- Prettier + prettier-plugin-tailwindcss — ESLint(코드 품질)랑 역할 나눠서, 포매팅은 Prettier가 전담

#### 인프라 / 자동화 AI (In Progress 💬)

- GitHub Actions — PR 올라올 때마다 lint + build 자동 검증
- Branch Protection Rule — main 직접 push 막고 PR 필수 설정
- Vercel로 배포 (예정)
- Dependabot - 라이브러리 디펜던시를 체크하여 자동 업데이트하는 PR 생성 (예정)
- Claude Code Action — PR 자동 코드 리뷰, 블로킹 아닌 제안 수준으로 운용 (예정)

이 부분에 있어서 제일 고심을 많이 했다, 라기 보다는 제일 많이 찾아보고 원리를 보려고 했던 부분이었다. 회사를 다닐때도 이런 부분은 직접 하지 않고 다른 팀원분이 해주셨었다. 확실히 해놓은 작업을 보는 것이랑 직접 하는 것은 간단한 설정일지라도 달랐다.
또한 AI를 많이 활용해보자는 취지가 있어서 디펜던시를 체크하는 봇이라던가, 아니면 클로드에게 코드 리뷰를 받는 그런 PR을 추가하고자 한다.
